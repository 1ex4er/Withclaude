## 3. Что написано (по порядку)

### 3.1 LX Agent (`agent/`) — программа для Windows-сервера DayZ
- Изначальная идея пользователя: управлять сервером с сайта Blackout (старт/стоп/рестарт, редактор конфигов,
  RCon, логи, моды) и раздавать тулзу **покупателям модов LX** (лицензия, конфиги модов, синхронизация БД).
- Сделано: агент сам подключается к сайту/боту по WSS (входящих портов нет), команды подписаны Ed25519 ключом
  сайта, защита от повтора, у каждого сайта свой `allow` (сайт LX по умолчанию видит только `lx.*` и статус),
  файлы только в разрешённых папках с бэкапом, проверка XML/JSON, BattlEye RCon (пароль читается из
  `beserver_x64.cfg`), логи, моды/SteamCMD, ключ агента шифруется DPAPI.
- Собирается в **`lx-agent.exe`** (Node SEA) в GitHub Actions; там же smoke-тест на Windows (DPAPI, автозапуск
  через Планировщик). Команды: `init`, `run`, `pubkey`, `install`, `uninstall`, `version`.
- **Не запускался на реальном DayZ-сервере.** ⚠️ Рестарт агентом собирает строку запуска из его config.json —
  до переноса модов/параметров из батника рестартовать агентом нельзя (сервер поднимется без модов).
- Синхронизация БД модов LX — не сделана (нужен формат БД модов).

### 3.2 Бот Blackout (`bot/`)
Модули (`bot/src/modules/`):
- **setup** — `/setup roles|channels|show|roles-list|backup`: роли и каналы выбираются выпадающими списками,
  хранятся в БД (`kv.settings`) поверх config.json.
- **status** — живое сообщение статуса сервера, presence бота, тревоги о падениях (нужен агент).
- **admin** — `/server …`, `/rcon …` с подтверждением опасных действий (нужен агент). Бан по SteamID офлайн
  (BE GUID = md5("BE"+SteamID64 LE)).
- **gamelogs** — ADM-лог → входы/выходы, килфид, игровой чат (нужен агент).
- **steam** — `/steam` (кнопка «Вписать SteamID» + «Войти через Steam» OpenID), `/check`, `/whitelist …`.
  Привязка вручную помечается «не подтверждён». Steam Web API (баны, возраст, часы DayZ, онлайн) — через тот же
  SOCKS-прокси. HunterEye: **публичного API нет**, предусмотрен подключаемый provider в `banCheck`.
- **verify** — «Я прочитал правила» → капча «нажми картинку» → окно ввода Steam → роль «Участник».
  Опция `verify.manualApproval` (выкл.) — заявка модераторам с кнопками.
- **applications** — анкета RP-персонажа (5 полей), в канал проверки с блоком проверки банов и кнопками
  Принять (роль Сталкер + вайтлист + ЛС) / Отклонить (причина в ЛС). «Зависшие» кнопки чинятся повторным нажатием.
- **tickets** — выбор темы → приватный канал → «Взять»/«Закрыть» → расшифровка в архив.
- **roles** — панель самовыдачи ролей (пользователю не нужна).
- **moderation** — `/warn` (3 → мут 1ч, 5 → бан), `/warns`, `/unwarn`, `/mute`, `/unmute`, `/kick`, `/ban` (темпбаны),
  `/unban`, `/clear`. Нельзя наказать равного/старшего по роли.
- **punishments** — `/punish @игрок <NLR|NonRP|PG|RDM|Meta|Бан> причина [срок]`, `/unpunish`, `/punishments`:
  роль на срок, автоснятие, история.
- **profile** — `/profile @игрок`: Discord, Steam, роли, варны, наказания, анкеты, тикеты, проверка банов.
- **automod** — скам-ссылки (поддельные домены Discord/Steam), чужие инвайты, флуд, повторы, масс-пинги.
- **antiraid** — волна входов → режим рейда (кик новых), `/raidmode`; антинюк по журналу аудита.

Прочее: автобэкап `bot.db` раз в сутки (VACUUM INTO, 14 копий, `bot/backups`), SQLite встроенный в Node
(`node:sqlite`, без нативных модулей), авто-«думает…» если обработчик не ответил за 0.6 с, лог опоздания событий.

### 3.3 Как решали проблемы (важно, чтобы не наступать снова)
1. **Discord заблокирован в РФ** — сервер LX в Москве. Нашли, что у бота LX есть `tpws` SOCKS `127.0.0.1:1080`.
   Сделана поддержка `DISCORD_PROXY=socks5h://127.0.0.1:1080` (REST через свой makeRequest, gateway — подмена
   конструктора `ws` в `bot/src/preload.js` до загрузки discord.js).
2. **«Приложение не отвечает» / 10062 Unknown interaction.** Лог показал: события gateway приходят пачкой с
   опозданием 36–61 с — соединение через tpws «замерзает». Решение без покупки VPS — **приём нажатий по HTTP**
   (`bot/src/http-interactions.js`): Discord шлёт POST на `https://lxmodschngz.ru/discord/interactions`
   (nginx-location на сайте LX → :3100), подпись Ed25519 проверяется (`DISCORD_PUBLIC_KEY`), первый ответ
   discord.js перехватывается на уровне REST и уходит телом HTTP-ответа. **Статус: код готов, на сервере не
   включено/не проверено** (шаги ниже). Если Discord не достучится до РФ-сервера — переносить бота на
   зарубежный VPS (рекомендовано изначально).
3. Команды `/setup` не были видны — у пользователя нет права «Администратор» в Discord. Сделано
   `commands.hideFromPlayers=false`: команды видны всем, доступ решают роли бота.
4. `git pull` → «dubious ownership» — `git config --global --add safe.directory /opt/blackout`.
5. Файлы с CDN Discord у пользователя не грузятся — `/setup roles-list` выводит текстом.
6. better-sqlite3 не собирался на Windows CI → заменён на `node:sqlite`.

## 6. Что осталось (по приоритету)
1. **Включить HTTP-нажатия** (последнее, на чём остановились):
   - на сервере: `git pull`, добавить `DISCORD_PUBLIC_KEY=<Public Key приложения>` в `bot/.env`, рестарт;
   - nginx сайта LX: `location /discord/interactions { proxy_pass http://127.0.0.1:3100; proxy_set_header Host $host; }`
     в server-блоке 443 lxmodschngz.ru, `nginx -t && systemctl reload nginx`, проверка `curl -X POST …` → 401;
   - Developer Portal → General Information → Interactions Endpoint URL = `https://lxmodschngz.ru/discord/interactions`.
   - Если Discord не сохраняет адрес — купить зарубежный VPS (NL/DE/FI, Ubuntu) и перенести бота
     (`/opt/blackout`, `bot/bot.db`, `bot/.env`).
2. Поднять роль бота в Discord.
3. Игровой сервер: узнать у пользователя — есть ли RDP к Windows, FTP/SFTP в панели, порт/пароль RCon; получить
   батник. Варианты: агент в «режиме панели» (без старт/стоп) или без агента (RCon напрямую + FTP).
4. Поддомен `bot.blackoutstalkerrp.ru` → 130.49.173.185 (A-запись в IHC), nginx + certbot, `publicUrl` бота —
   для «Войти через Steam» и подключения агента.
5. Код сайтов Blackout и LX — пользователь выложит в GitHub (приватные репо), встроить админку.
6. Сделать репозиторий приватным.
7. Идеи на будущее (пользователь пока не выбрал): связь банов Discord↔игра, смена персонажа, ивенты с записью,
   статистика из логов, еженедельный отчёт.
